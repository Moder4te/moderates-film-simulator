## 목표 룩의 정의 — 랩 스캐너와 무엇이 다른가

같은 네거티브를 두 방식으로 읽으면 그레인이 다르게 나온다. **차이의 대부분은
광학이 아니라 의도된 처리다.**

| | 랩 스캐너 (Frontier · Noritsu) | 미러리스 픽셀시프트 |
|---|---|---|
| 크로마 NR | Image Intelligence · EZ Controller가 **크로마를 휘도보다 세게 누른다** | 없음 |
| 크로마 서브샘플링 | JPEG 4:2:2 / 4:2:0 → 색 해상도 절반 | 없음 |
| 필름면 화소 피치 | 약 12µm (35mm 6MP 출력) — **입자 덩어리와 같은 크기** | **3.79µm** (4샷) · **1.89µm** (16샷) |
| 색 취득 | 트라이리니어 CCD (디모자이크 없음) | **픽셀시프트 → 디모자이크 없음** |
| 광원 | 확산 (칼리에 — 그레인 대비 낮음) | 대개 더 지향적 |

> **픽셀시프트라 디모자이크 아티팩트가 없다.** 4샷은 센서를 1픽셀씩 옮겨 모든 화소
> 위치에서 R·G·B를 실제로 측정한다. 베이어 보간이 아예 없으므로, **관찰되는 컬러
> 그레인은 필름의 실제 구조이지 스캔 산물이 아니다.** 목표를 여기 두는 것이 맞다.
>
> 단서 하나 — 4샷은 2×2 중 G 광다이오드가 둘이라 **녹 채널만 샘플이 2배**다. 캡처
> 단계에서 G가 R·B보다 약 1.41× 깨끗하다. 측정할 때 이걸 필름 특성으로 읽으면 안 된다.

### 실제 컬러 네거티브 그레인의 구조

```
유제 3겹 · 각 층의 은입자가 통계적으로 독립  →  RGB 잡음이 무상관 → 크로마 그레인은 본질적
층마다 다이클라우드 크기가 다름              →  청감층(황색 염료)이 가장 조대
밀도가 오를수록 현상 입자가 겹친다            →  인화 명부에서 덩어리가 굵어진다
오렌지 마스크가 청색을 크게 흡수              →  어떤 스캔에서도 청 채널이 가장 시끄럽다
```

### G1 — `colorMode` 기본값을 `"rgb"`로

**현행이 목표와 정반대다.**

```js
// apps/finish/src/params.js
colorMode: "mono",   // 세 채널이 같은 필드를 공유 → 채널 상관 1.000 → 크로마 0
```

`mono`는 한 필드를 전 채널에 복사한다. 채널 간 상관이 정확히 1.0이므로 **순수 휘도
잡음**이고, 이것이 바로 랩 스캐너 룩이다.

`rgb` 모드의 채널 독립성은 이미 제대로 되어 있다(실측):

```
R↔G 0.036   G↔B −0.033   R↔B 0.037     ← 사실상 완전 독립
```

- **비용** 필드 생성 1벌 → 3벌. 출력 버퍼·`imageData`는 그대로
- **같이 할 것** `mono`/`rgb`라는 이름을 **`랩 스캐너` / `카메라 스캔`**으로 바꾼다.
  실제로 그 둘을 가르는 토글이다. 라벨일 뿐이라 불변식 3(마감 앱에 색 없음)에 안 걸린다

### G2 — 채널별 cell 차등

**파라미터 이름·주석이 이미 이걸 주장하는데 구현이 따라가지 않는다.**

```js
// params.js — "크기 분화"라고 적혀 있다
dyeSpread: 50,  // 채널별 입자 크기 분화 0~100. 유제층 3겹 재현(청색 조대).

// format.js — 실제로는 진폭만 만든다
const amp = (f) => 1 + (f - 1) * spread;
amps = { r: amp(1.23), g: 1.0, b: amp(1.76) };
```

**근거.** Selwyn 입상도에서 고정 개구의 σ ∝ d(입자 지름)이다. 즉 이미 있는 진폭비
1.23 / 1.0 / 1.76 **자체가 크기비의 방증**이다. 그런데 값 노이즈에서는 cell을 키워도
RMS가 변하지 않으므로(실측 99~100%) **크기와 진폭을 따로 줘야** 물리가 재현된다.

실측 (cell 6.0 기준):

| 채널 | cell | 상관길이 | RMS |
|---|---|---|---|
| R | 7.38 | 7px | 99% |
| G | 6.00 | 6px | 100% |
| **B** | **10.56** | **10px** | 100% |

- **비용 0.** `grainfield.generate`에 채널 루프가 이미 있다. `cell`을 채널별로 넘기면 끝
- **버퍼도 `imageData`도 안 늘어난다**
- ⚠️ **비율은 측정으로 채운다**(M1). 진폭비 1.23/1.0/1.76이 어떻게 측정된 값인지 코드에
  기록이 없어, Selwyn 논거를 그대로 크기비로 옮기려면 그 측정이 고정 개구 RMS였다는
  전제가 필요하다. **손잡이만 만들고 기본값은 1.0으로 두다가 측정 후 채운다**

### G3 — 존별 클럼프 크기

개별 은입자 크기는 유제가 정하므로 톤과 무관하다. 그러나 스캔에 찍히는 것은 개별
입자가 아니라 **현상된 입자의 덩어리**이고, 그 크기는 밀도를 따른다. 하늘의 그레인이
거친 얼룩으로 보이는 이유다.

**필드를 다시 굽지 않고 레이어를 확대한다.** 실측상 두 방법이 같은 결과를 낸다:

| 방법 | 상관길이 | RMS | 비용 |
|---|---|---|---|
| 기준 (cell 6.0) | 5px | 100% | — |
| **레이어 확대 ×1.35** | **7px** | **99%** | `transform` 1회 |
| 필드 재생성 cell 8.1 | 7px | 99% | 버퍼 3벌 + imageData 3벌 |
| 블러 σ=3 (대조군) | 9px | **64%** | 대비 붕괴 |

`ps.scaleLayer`는 할레이션 축소 피라미드 때 만들어 **이미 실기 검증된 함수**다.
**`imageData` 한 벌 재사용이 유지된다.**

대조군이 이 저장소의 원래 판단을 독립적으로 재확인한다 — 블러는 크기는 키우지만
대비를 64%로 무너뜨린다("블러는 큰 blob을 못 만든다").

- ⚠️ **축소는 하지 않는다.** 레이어가 캔버스보다 작아져 가장자리에 구멍이 난다.
  필드를 미드톤 기준의 1/1.15로 굽고 세 존을 전부 확대 쪽으로 잡는다
- ⚠️ **"세 존이 텍스처를 공유한다"는 기존 주석이 깨진다.** 밀도-클럼핑 근거로 다시 쓴다
- ⚠️ **실기 확인 항목** — 확대는 중심 고정이라 캔버스 정중앙에서 두 존의 패턴이 거의
  같다. 계산상 반경 약 23px 밖에서 상관이 풀리지만(6000px 이미지에서 무시할 크기),
  매끈한 하늘에서 보이는지 본다. 보이면 `ps.scaleLayer`의 `offset`(지금 0으로 박혀 있음)에
  값을 줘 전 영역에서 어긋나게 한다. 확대 여백이 충분해 가장자리는 안전하다

### G4 — 명부 이득 보상 + 교차점 존 유도

**증상: 존 슬라이더를 바꿔도 결과가 거의 같다.** 원인이 둘이다.

**① 미드톤 존이 톤 범위의 84%를 덮는다.**

| 존 | Blend If 실제 구간 | 덮는 폭 |
|---|---|---|
| shadow | `[0, 40, 45, 125]` | 49% |
| **midtone** | `[20, 100, 155, 235]` | **84%** |
| highlight | `[130, 210, 215, 255]` | 49% |

세 범위를 독립으로 잡고 각각 ±feather(40)를 더하니 커버리지 합이 182%다. 무엇을
넣든 합이 같은 종 모양이 된다. 게다가 **가중치 합이 0.00~1.31로 흔들려**, 슬라이더를
전부 같게 놔도 톤에 따라 그레인 양이 31% 출렁인다.

**교차점 두 개에서 유도하면 합이 항상 정확히 1이다**(실측 이탈 0.0e+0):

```js
function zoneRanges(c1, c2, feather) {
  const h = feather / 2;
  return {
    shadow:    [0, 0, c1 - h, c1 + h],            // 아래엔 크로스페이드할 존이 없다
    midtone:   [c1 - h, c1 + h, c2 - h, c2 + h],
    highlight: [c2 - h, c2 + h, 255, 255],
  };
}
```

파라미터가 6개(범위 3쌍) → **2개**로 줄고, 겹침·구멍이 원천적으로 불가능해진다.
끝 존의 의미 없는 바깥 페더도 여기서 같이 닫힌다.

**② Overlay 이득이 명부에서만 Weber를 깬다.**

| L | 20 | 42 | 85 | 128 | 170 | 212 | 240 |
|---|---|---|---|---|---|---|---|
| 상대대비 | 50% | 50% | 50% | 50% | 25% | **10%** | **3%** |

**암부는 이미 완벽하다** — `2·min(b,1−b)`가 L<128에서 Weber 상대대비를 정확히 50%
상수로 유지한다. **보상하면 과해진다.** 명부만 무너지고, 이건 물리적으로도 틀렸다 —
실제 필름에서 하늘(= 네거티브 고밀도)은 그레인이 가장 잘 보이는 자리다.

차별화 지수(기본 25/45/15 vs 평탄 45/45/45의 최대 상대차):

```
현행                     25%
교차점 방식              31%
교차점 + 명부 보상 ×2.2  64%
```

- **마이그레이션 필요** — 기존 프리셋의 `shadowRange`/`midtoneRange`/`highlightRange`
  → 교차점 2개
- `HIGHLIGHT_GAIN` 2.2는 명부 존 중심(L≈212)의 이득 0.34를 미드톤 1.0에 맞추는 2.9의
  **부분 보상**이다. 전량 보상하면 슬라이더가 34에서 100%에 닿아 상단이 죽는다. 육안 조정 대상
- ⚠️ **G3와 같이 켜고 한 번에 맞춘다.** 크기가 굵어지면 같은 진폭도 더 세 보이므로
  2.2는 G3 적용 후 내려갈 가능성이 크다

### G5 — 옥타브 회전

외부 검토가 "격자를 숨기려 다시 블러를 거는 모순"을 지적했다. **프레이밍은 성립하지
않지만**(원래 문제는 블러 반경 ≈ blob 크기였고, `gridSmooth`는 블러 ≈ cell/3.3이라 대비
96~99%가 남는다) **약점 자체는 실재했다.** 측정해 보니:

| | 격자 점수 (낮을수록 좋음) | 남는 대비 |
|---|---|---|
| 현행 (정렬, 블러 없음) | 0.077 | 100% |
| 현행 + `gridSmooth` 블러 | 0.066 | 97% |
| 옥타브 오프셋만 (검토자 제안) | 0.070 | 93% |
| **옥타브 회전** | **0.018** | 95% |
| 회전 + 오프셋 | 0.022 | 87% |

- **검토자 제안(오프셋)은 통하지 않는다.** 두 옥타브를 서로 어긋나게 할 뿐, 각 옥타브가
  자기 축 정렬 격자를 그대로 갖는다
- **회전이 답이다** — 4.3배, 대비 손실 5%. 오프셋을 더해도 나아지지 않으니 회전만 한다
- **`gridSmooth`는 이름값을 못 하고 있다** (0.077 → 0.066, 14%)
- ⚠️ **`gridSmoothForIso`를 지표만 보고 지우지 말 것.** 육안 튜닝값이라 잡으려던 것이
  격자선이 아니라 **smoothstep blob의 각진 면**일 수 있다. 다른 인공물이다.
  **회전을 넣고 → `gridSmooth`를 0으로 두고 → 눈으로 본 뒤** 결정한다

## 착수 순서 — 세 갈래

이 저장소가 `MID_GRAY_OFFSET`에서 이미 쓴 방법이다.

> 기본값을 0으로 두고 손잡이만 만들어 둔다. 기준이 되는 정답 스캔이 없으므로
> 추정값을 박아 넣는 것은 근거 없는 이동일 뿐이다.

그때는 정답 스캔이 없었다. **그레인 쪽은 이제 있다.**

| 채널 간 상관 | 크로마 그레인이 실제로 얼마나 강한가 | G1 검증 |
| 밀도 단계별 위 세 가지 | 존별 클럼프 크기·진폭 곡선 | G3 · G4 |
| 필름별 위 세 가지 | **필름별 유효 입자 크기** | STATUS 항목 해제 |

**합성 필드에 쓰는 지표와 같은 것들이다.** 그래서 `tools/measure-scan.js`가 스캔에서,
기존 검사가 생성 필드에서 **같은 숫자를 뽑는다** — 튜닝이 "눈으로 맞추기"에서
"숫자 맞추기"로 바뀐다. 색 쪽이 이미 하고 있는 것(TDS → 정합성 전수 대조)을 그레인에도 세운다.

### 리그 제약 — 대부분 측정에 영향이 없다

리그는 **A7R V + F마운트 1:1 매크로(E마운트 어댑터) + 픽셀시프트**다. 두 가지가
걸리는 것으로 보였는데, 따져 보니 대부분 무관하다.

**"전 프레임이 정확히 안 잡힌다"** — 측정에 전 프레임이 필요 없다. 재는 것은
이미지가 아니라 **통계량**이고, 그레인은 공간적으로 정상(stationary)이라
**중앙 1000×1000px 크롭이면 표본 100만 개**다. RMS·상관길이가 안정되는 데 필요한
양의 수십 배다. 배율이 정확히 1:1이 아니어도 **비율만 쓰므로 스케일이 약분된다.**

**"어댑터라 렌즈 성능이 떨어진다"** — F→E 어댑터는 **유리가 없는 순수 스페이서**라
(포컬리듀서가 아닌 한) 광학 성능을 떨어뜨릴 경로가 없다. 실제 위험은 **편심·틸트**와
**렌즈가 1:1에 최적화됐는지**인데, **둘 다 중앙 크롭으로 회피된다** — 주변부를 안 쓴다.

**남는 진짜 문제는 축상 색수차 하나다.** R·G·B의 초점면이 어긋나면 채널마다 선명도가
달라지고, 그것이 재려는 것(채널별 상관길이)에 정확히 오염된다. 구형 매크로에서 흔하다.

### 렌즈 보정이 필요한 측정과 아닌 것

축상 CA 보정은 **한 종류의 비교에만** 필요하다. 이 구분이 작업량을 크게 줄인다.

| 비교 | 렌즈 보정 | 이유 |
|---|---|---|
| **밀도 단계 간** (G3) | **불필요** | 같은 채널끼리 비교 — PSF가 구적 차에서 상쇄된다 |
| **필름 간** (STATUS 항목) | **불필요** | 같은 이유 |
| **채널 간** (G2) | **필요** | PSF가 채널마다 다르다 |

**즉 G3와 필름별 측정은 캘리브레이션 없이 바로 할 수 있다.** 보정이 필요한 것은 G2 하나다.

### 퍼포레이션을 자와 캘리브레이션으로 쓴다

35mm 퍼포레이션은 **ISO 1007로 규격화**돼 있다(피치 4.75mm). 모든 스트립에 붙어 있는
정밀 자이고, 가장자리는 백라이트 실루엣이라 **물리적으로 완벽한 고대비 직선 엣지**다.

- **스케일 기준** — 여러 피치를 가로질러 재서 평균 내면 µm/px가 서브퍼센트로 나온다.
  배율이 1:1이 아니어도, 프레임마다 달라도 무관해진다
- **채널별 PSF** — 슬랜티드 엣지(ISO 12233)로 채널별 엣지 확산 함수를 그대로 뽑는다.
  이것이 G2에 필요한 보정값이다

**한 장에서 둘 다 나온다.** 별도 타깃이 필요 없다.

초점은 문제되지 않는다 — 퍼포레이션(베이스면)과 유제면 간격이 10~20µm인데
f/5.6에서 DOF가 ±21µm다(허용 착란원 1px 기준).

### 센서 잡음을 뺀다 — 같은 자리를 두 번 찍는다

**오렌지 마스크가 청색을 크게 흡수해 청 채널만 광량이 부족하다.** 그래서 측정된
청색 RMS에는 필름 그레인과 센서 샷노이즈가 섞이고, 빼지 않으면 **B의 진폭비를
과대평가**한다. ⚠️ 지금 코드의 1.76이 이 오염을 포함한 값일 가능성도 있다 —
측정 방법이 기록돼 있지 않아 확인할 수 없다.

```
같은 패치를 픽셀시프트로 2회 촬영
차영상 = √2 × 센서 잡음        (필름 그레인은 고정 패턴이라 정확히 상쇄된다)
σ_필름² = σ_측정² − σ_센서²
```

채널별로 따로 나오므로 청 채널 문제에 정확히 대응한다. **두 번 찍는 것으로 끝난다.**

### 촬영 조건

| | 권장 | 이유 |
|---|---|---|
| 크롭 | 중앙 1000×1000px | 주변부 소프트·편심·필드곡률을 전부 회피 |
| 조리개 | **f/4~5.6 고정** | 회절 왜곡 −1.9~−3.5%. **값보다 전 세션 통일이 중요하다** |
| 모드 | **16샷** | 1.89µm/px면 ISO 400 그레인이 5.3px라 상관길이를 잴 여유가 있다. 4샷 2.64px는 아슬아슬 |
| 필름 평면성 | **유리 홀더** | 렌즈보다 이쪽이 더 큰 오차원이다. DOF가 ±21µm인데 홀더 없는 필름은 그보다 훨씬 휜다 |
| 광원 | 고연색 · 청색 출력 충분한 것 | 마스크가 청색을 먹는다 |
| 노출 | **청 채널 기준 ETTR** | 가장 광량이 부족한 채널의 SNR을 살린다 |

**장비를 새로 사지 않는다.** 실제로 신경 쓸 것은 렌즈가 아니라 **필름 평면성**과
**두 번 찍기** 둘이다.

### 절차

```
1. 유리 홀더에 스트립 고정. 퍼포레이션이 프레임에 걸치게 배치
2. f/5.6 · 16샷 · 청 채널 ETTR로 같은 자리를 2회 촬영
3. 밀도 단계별로 반복 (균일 노출 구간 여러 곳)
4. 필름 종류별로 반복 — 조리개·배율·광원을 절대 바꾸지 않는다
5. tools/measure-scan.js
   ├ 퍼포레이션에서  µm/px  +  채널별 PSF σ
   ├ 중앙 크롭 고역통과 →  채널별 RMS · 자기상관 · 채널 간 상관
   ├ 두 장 차영상에서 센서 잡음 → 구적으로 뺀다
   └ 채널 간 비교에만 PSF를 구적으로 뺀다
```

### ⚠️ 회절 — 절대값은 못 잰다. 비율은 쓸 만하다

1:1에서는 유효 조리개가 **N_eff = N × 2**다.

| 조리개 | N_eff | 에어리 지름 B / G / R |
|---|---|---|
| f/4 | f/8 | 8.8 / **10.7** / 12.7 µm |
| f/5.6 | f/11.2 | 12.3 / **15.0** / 17.8 µm |
| f/8 | f/16 | 17.6 / **21.5** / 25.4 µm |

**ISO 400의 다이클라우드가 10µm다.** f/4에서도 에어리 지름이 그것과 맞먹는다.
스캔이 그레인에 대해 회절 한계이므로, 측정한 상관길이는 실제 덩어리 크기가 아니라
**그 상한**이다.

다행히 **비율 쪽은 안전한 방향으로 틀어진다.** 에어리 지름이 λ에 비례하니 회절은
**적색을 가장 크게 부풀린다**(R 12.7 vs B 8.8µm). 필름은 반대로 청색이 가장 굵다.
두 효과가 상쇄 방향이라 **측정된 B/G 크기비는 실제보다 과소평가**된다. 보수적이다.

**얼마나 틀어지는지 계산해 뒀다.** 16샷(1.89µm/px)에서, 필름의 참값을 진폭비와 같다고
(Selwyn σ∝d) 가정하고 회절 PSF를 구적으로 얹었을 때:

| 조리개 | PSF σ(px) R / G / B | 측정될 B/G | 참값 1.760 대비 |
|---|---|---|---|
| **f/4** | 1.16 / 0.98 / 0.80 | 1.727 | **−1.9%** |
| **f/5.6** | 1.62 / 1.37 / 1.12 | 1.698 | −3.5% |
| f/8 | 2.31 / 1.96 / 1.60 | 1.642 | −6.7% |

R/G는 세 경우 모두 1.222~1.228로 참값 1.230과 거의 같다. **회절만 놓고 보면
f/4~5.6에서 채널비 오차가 수 % 수준이고 전부 과소평가 방향이다.**

미지수는 회절이 아니라 **축상 CA**다. 렌즈마다 다르고 계산으로 못 낸다 —
그래서 퍼포레이션 엣지로 **재서** 뺀다(위 참조).

따라서:

- **절대 크기(µm)로 `micronsForIso`를 갈아끼우지 않는다** — 과대평가가 된다
- **비율만 쓴다** — 채널 간·밀도 단계 간·필름 간. 회절이 공통으로 걸려 나눗셈에서 약분된다

### 참고 — 이 셋업의 스케일

1:1이면 35mm 프레임이 센서를 꽉 채운다. 필름면 화소 피치 **3.79µm/px**(4샷) ·
**1.89µm/px**(16샷).

| | ISO 400 cell | 채널 차등 시 R / G / B |
|---|---|---|
| 4샷 9504px | 2.64px | 3.25 / 2.64 / **4.65** |
| 16샷 19008px | 5.28px | 6.49 / 5.28 / **9.29** |

4샷 ISO 100에서는 G가 1.43px로 거의 백색 잡음 영역이다. **이 구간에서 채널 크기
차등이 특히 중요하다** — 청색을 2.52px로 올려야 "덩어리"로 읽힌다.

## 검증

### 노드에서 (검사로 못 박는다)

`grainfield` · `format` · `zoneRanges`는 전부 순수 함수라 값 검증이 가능하다.

| 검사 | 항목 |
|---|---|
| 격자 점수가 임계 아래인가 | G5 |
| 채널 간 상관이 0에 가까운가 | G1 |
| 채널별 상관길이가 R<G<B 순인가 | G2 |
| 존 가중치 합이 1인가 | G4 |
| 레이어 확대가 RMS를 보존하는가 | G3 |

> ⚠️ **`blendRangeFor`가 지금 `grain.js` 안에 있어 노드에서 못 부른다**(맨 위에서
> `photoshop`을 require한다). `samePath`를 `shared/paths.js`로 올렸던 것과 같은 상황이다.
> `zoneRanges`로 다시 쓰는 김에 `core/optics/`로 올린다 — 못 부르는 코드는 검사 없는
> 코드와 같다.

**검사는 일부러 깨뜨려 확인한다.** 이 저장소는 통과 표시를 내면서 아무것도 검사하지
않던 전례가 두 번 있다.

### 실기에서만 되는 것

- G1 — 크로마 그레인이 과한가 (픽셀시프트 스캔 원본과 나란히 놓고)
- G3 — 캔버스 중앙의 존 간 패턴 상관이 보이는가
- G5 — `gridSmooth`를 0으로 내려도 되는가 (blob 각진 면이 남는지)
- 프리셋 4종(`35mm Classic` · `Night Halation` · `120 Fine` · `CineStill 800T`) 재확인

## 열리는 STATUS 항목

M1이 끝나면 [`STATUS.md`](./STATUS.md) 데이터 신뢰도에서 다음이 **추정 → 실측**으로 바뀐다.

- **그레인 µm 대응은 추정** — 비율로 한정하면 실측이 된다(절대값은 회절 때문에 남는다)
- **유효 입자 크기가 필름별로 다르지 않다** — 필름별로 재면 값이 생긴다
- (신규) 진폭비 1.23 / 1.0 / 1.76의 근거 — 지금 코드에 방법 기록이 없다

**남는 것** — 스캐너 파라미터·텅스텐 캐스트·`MID_GRAY_OFFSET`은 이 리그로 안 풀린다.
기준이 되는 "정답 색"이 필요하고 그건 별개의 확보 경로다.
