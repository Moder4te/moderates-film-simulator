### 도구 이분화 — 엔진과 마감을 나눈 이유

**2026-07-25 결정.** 애초엔 하나였으나 둘로 갈랐다.

| | 엔진 `com.filmsim.photoshop` | 마감 `com.filmsim.finish` |
|---|---|---|
| 담당 | 색 — 유제 + 스캐너 + 조정 | 할레이션 · 그레인 (공간 연산) |
| 성격 | 순수 계산 | Photoshop 액션 |
| 입력 | 16bit RGB (ProPhoto 권장) | **8bit JPEG이 정상 입력** |

**경계가 기술적으로 명확하다** — LUT에 담기는 것은 색, 담기지 않는 것(공간 연산)은
마감. 애매한 중간이 없다.

**왜 물리적으로 갈랐나.** 섞여 있으면 마감을 손보다 색이 망가질 수 있는데, 그 실수는
결과를 보기 전까지 드러나지 않는다. 나눠 두면 마감 플러그인에 색 코드가 **아예 들어
있지 않아** 물리적으로 불가능해진다(불변식 3으로 강제).

### 실측으로 확정된 런타임 제약

| 기능 | 상태 | 설계 영향 |
|---|---|---|
| WebGL / WebGL2 | ❌ 전부 부재 | GPU 가속 포기 |
| `Worker` | ❌ undefined | **JS 멀티스레드 불가.** 모든 연산 단일 스레드 |
| `OffscreenCanvas`, `canvas.getImageData` | ❌ | 캔버스 픽셀 리드백 불가 → 컬러휠은 DOM+translate |
| WebAssembly | ✅ 실행됨 | 다만 **불필요** — 순수 JS로 목표 달성 |
| `imaging.getPixels` / `putPixels` | ✅ 검증됨 | **LUT 적용의 유일한 경로** |
| Color Lookup 레이어 **생성** | ✅ | 레이어는 만들어짐 |
| Color Lookup에 **.cube 주입** | ❌ **불가 확정** | batchPlay가 바이너리를 못 나름 |
| batchPlay descriptor의 바이너리 | ❌ `ByteArray is not supported` | ArrayBuffer·Uint8Array 모두 거부 |

> **대조 실험이 결정적이었다.** Photoshop 자신의 내장 `.cube` 경로를 넣어도 동일하게
> 무효과였다. 즉 우리 파일 형식 문제가 아니라 **batchPlay의 구조적 한계**다.

### 성능 — WASM을 뺀 근거

목표를 전부 실측으로 확정했다(60.2MP / 16bit / ProPhoto).

| 항목 | 목표 | 실측 |
|---|---|---|
| 드래그 중 프록시(512px) | 15fps | **29fps** (34ms) |
| LUT 재생성 33³ / 65³ | — | **1ms / 2ms** → 캐시 불필요 |
| 풀해상도 적용 (60.2MP) | 20초 이내 | **3.4초** |

**병목은 전송이 아니라 연산(59%)이다.** 착수 전 예상과 반대였다 → 타일 분할은 속도
대책으로 무의미하고 메모리 대책으로만 의미가 있다.
**UXP의 JS 처리량이 Node와 같은 수준**(0.033~0.051 vs 0.046 µs/px)이라 WASM을 뺐다.

## 색 엔진

### TDS에 있는 것과 없는 것

**있다** — D-logE 특성곡선(층별), 분광 감도, 분광 염료 농도, Print Grain Index.
**없다** — 오렌지 마스크 제거/네거 반전 알고리즘, 스캐너 색 렌더링, 인화지 응답.

> 사람들이 "Portra 400 색감"이라 부르는 것의 **절반 이상이 없는 쪽에 있다.**
> 그래서 스캐너 스테이지는 옵션이 아니라 **룩의 주력**이다.

- **에멀전 스테이지 (TDS 기반)** = 물리적 뼈대. 데이터가 말하는 대로.
- **스캐너 스테이지 (경험적 튜닝)** = 감성 손잡이. 여기서 룩이 완성된다.

### ⚠️ RMS 그래뉼래러티는 더 이상 발행되지 않는다

착수 전엔 TDS의 RMS 값으로 물리적 입자 크기를 유도할 계획이었다. 최신 Kodak TDS에는
그 값이 없고, 본문에 명시돼 있다.

> Print Grain Index … **It replaces rms granularity and has a different scale which
> cannot be compared to rms granularity.** (E-4050 / E-7022, p3)

PGI는 물리적 크기가 아니라 **확산 인화물의 지각적 거칠기**다. 따라서 µm 유도가 불가능
하고, 그레인은 **한 점 보정 + 상대 스케일**로 간다(감성 근사 범위).

### 스캐너 화이트포인트 정규화가 필요한 이유

실효대비(곡선 기울기 × printGamma)가 1을 넘는 층은 v=1에서 출력이 1.0을 초과한다.
그대로 두면 **층마다 다른 지점에서 잘려 하이라이트의 색이 무너진다.**

여기서 **두 번 틀렸다.**

1. **세 층 공통 스칼라 이득** → 이득이 가장 가파른 층(청감)에 맞춰져 적감층이 더 눌리고
   전체가 어두워졌다.
2. → **채널별 소프트 롤오프**로 바꿨다. 상한 근처만 부드럽게 눌러 1.0으로 수렴시키고
   무릎 아래는 손대지 않는다.

**이득은 노광 보정 0 기준으로 고정**한다. 현재 노광에서 다시 계산하면 노광 보정이
스스로를 상쇄한다(실제로 +1스톱이 0스톱보다 어두워졌다).

### 필름 종류가 반전 부호를 정한다

| | color-negative | color-reversal | bw-negative |
|---|---|---|---|
| 노광↑ | 농도↑ | **농도↓** | 농도↑ |
| 정규화 기준 | 기준 그레이 → 0.18 | **가장 밝은 입력 → 1.0** | 기준 그레이 → 0.18 |
| `printGamma` | ≈ 1/γ_G | **1.0** (슬라이드 대비가 곧 룩) | ≈ 1/γ |
| 층 | 3 | 3 | **1** |

**리버설 기준을 Dmin으로 잡으면 안 된다.** 그렇게 했다가 최대 출력이 0.0099까지 떨어져
화면이 새까맣게 나왔다. 스캐너가 하는 일은 "필름이 낼 수 있는 최저 농도"가 아니라
**"장면의 가장 밝은 곳"을 흰색에 놓는 것**이다.

### Lightroom 프로파일 — .cube가 다리다

```
film.js → lut.js → .cube → [ACR New Profile 또는 직접 생성] → .xmp
```

한동안 `crs:Table_<ID>` 인코딩을 "비공개 포맷"으로 단정하고 페이로드를 직접 해독하려
했다. 실제로는 **Adobe가 변환기를 Photoshop 안에 넣어놨고**, 포맷도 DNG SDK의
`dng_big_table`로 공개돼 있었다.

> **교훈 — 남의 파일 포맷을 뜯기 전에 그 회사가 만드는 도구를 먼저 찾아라.**
> 검색 한 번이면 나올 것을 디코더에 몇 시간 썼다.
> 순서: ① 공식 도구·SDK·문서 → ② 오픈소스 구현 → ③ 직접 해독

색공간은 추측할 필요가 없었다 — New Profile 대화상자가 직접 물어본다(ProPhoto RGB
선택 시 엔진 원본 그대로). **엔진 → .cube → ACR 프로파일이 Difference 판정상 일치**함을
실측했다(2026-07-25).

### 프로파일 배포 — 직접 생성과 동봉을 **둘 다** 둔다 (v2.2.0)

한동안 "엔진이 계속 바뀌는 단계라 사용자가 직접 생성하는 쪽이 맞다"로 두고, 동봉은
데이터가 안정된 뒤로 미뤄 뒀다. v2.2.0에서 **둘 다 두는 것으로 정리했다.**

- **직접 생성** (`.xmp` 세트 전체 버튼) — 엔진을 고쳐도 항상 최신. 대신 버튼을 눌러야 한다
- **동봉** (`lrplugin/`) — 프로파일 18종을 담아 릴리스에 올린다. 설치 직후 바로 쓴다

**둘이 충돌하지 않는 이유** — 동봉본은 `tools/build-lrplugin.js`가 **빌드 시점에 엔진에서
다시 굽는다.** 손으로 관리하는 사본이 아니라 산출물이라, "구현이 둘이 되면 갈라진다"가
성립하지 않는다. 빌드가 카탈로그(`Profiles.lua`)까지 생성하고, 두 조합이 같은 `RGBTable`을
내면(=색이 실제로 같다는 뜻) 빌드가 실패한다.

**미룰 이유가 사라진 지점** — 프로파일이 걸리는 조건이 실기로 다 밝혀졌다
(`Look.UUID` · `Parameters.RGBTable` · `CameraProfile`). 그 전에는 동봉해도 조용히 안
걸릴 수 있었다. → [`STATUS.md`](./STATUS.md)의 LrC 표

## 광학 (마감)

| 결정 | 근거 |
|---|---|
| **입자 크기는 필름면에서 고정** | 최종 이미지에서 달라 보이는 것은 확대율 차이. `grain_px = µm/1000 × px/mm` |
| 그레인 슬라이더 = **감도(ISO)** | 감도가 곧 입자 크기라 근거가 하나로 합쳐지고 사진가에게 익숙하다 |
| **값 노이즈**로 생성 | 가우시안 블러는 큰 blob을 못 만든다 — 반경을 키우면 대비가 함께 떨어져 mush가 된다 |
| 채널차는 **크기가 아니라 진폭** | Vision3 500T 스캔 4장 실측: 상관길이는 세 채널 동일, RMS가 R1.23/G1.0/**B1.76** |
| 디퓨전 기본 = **변위(확산)** | 블러는 미세 선을 흐리게 남기고, 확산은 조각낸다 |
| 할레이션 = **다중스케일** | 단일 가우시안은 타이트한 코어와 넓은 꼬리를 동시에 못 낸다 |
| 할레이션 추출 = **적색 채널 구동** | 할레이션은 물리적으로 적색 현상. 휘도로 뽑으면 포화 적색 네온을 놓친다 |
| 할레이션 번짐 = **원반(disk)** | 베이스 뒷면 반사라 종형이 아니라 경계가 뚜렷하다(육안 확인) |
| 존 마스킹 = **Blend If** | 마스크 채널 생성 없이 페더링까지 얻고 완전 비파괴 |
| 할레이션 채널차 R 최대 | R/G/B 동일 반경이면 그냥 글로우가 된다 |

**Blend If를 쓴 부수 이유** — median·threshold 디스크립터가 미채록이라 채록된
`addNoise`·`gaussianBlur`·`selectChannel`만으로 근사해야 했다.

## 법률

### 라이선스 — PolyForm Noncommercial 1.0.0

**소스 공개 + 비상업 용도만.** 진짜 OSI "오픈소스"(MIT/GPL)는 정의상 상업적 사용을
막지 못하므로, "오픈소스/비상업" 방침에는 소스공개형 비상업 라이선스가 맞다.

지킨 제약 (선택지를 열어두기 위해 착수 때부터 적용):

- **TDS PDF 자체는 재배포하지 않는다.** 문서는 저작물이다. `.gitignore`에 `tools/tds/`, `*.pdf`.
  수치는 사실 정보라 배포에 문제없고, `source` 필드에 출처를 기록해 투명성을 확보한다.
- **GPL/NC 데이터 소스를 피한다.** GPL 데이터를 들이면 전체가 GPL로 전염돼 라이선스를
  고를 자유가 사라진다.
- **상표는 명목적 사용만.** 로고·서체·트레이드드레스 미사용, "공식·인증·정품" 표현 금지.

### 하면 안 되는 것

상용 제품(NLP 등)의 스캐너 프로파일에 **맞춰 파라미터를 피팅하는 것**. 포맷 이해를 위해
남의 파일을 읽는 것(상호운용성 분석)과 그 데이터를 가져다 쓰는 것(복제)은 다르다.

## 뒤집힌 결정 — 기록해 둔다

같은 함정을 다시 밟지 않기 위해 남긴다.

| 당초 | 최종 | 왜 |
|---|---|---|
| GPU/WebGL 가속 | 순수 JS 단일 스레드 | WebGL 부재. **성능 목표는 오히려 초과 달성** |
| Color Lookup 조정 레이어 | putPixels 픽셀 레이어 | batchPlay가 LUT 바이너리를 못 나름 |
| WASM 필수 | 미도입 | 사면체 조회가 v1 grading보다 10배 싸다. UXP JS = Node 수준 |
| v1 그레이딩 제거 | JPEG 후처리용으로 존속 | 프로파일 현상 후 미세 조정 자리가 있다 |
| 기준 해상도 2단계 | 3단계 + 직접 입력 | "문서 그대로"가 물리적으로 옳은 기본값인데 2단계로는 표현 불가 |
| 채널별 그레인 **크기** 차등 | **진폭** 차등 | 실측이 크기 차이를 지지하지 않았다 |
| 그레인 크기 상한 10 (6µm) | ISO 50~3200 (4~25µm) | 상한은 블러 mush 회피용이었는데 값 노이즈로 불필요해짐 |
| ACR 프로파일 = 비공개 포맷 | Adobe 변환 도구 존재 | 페이로드를 뜯기 전에 도구를 찾았어야 했다 |
